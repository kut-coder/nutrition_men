# Задача: точечно доработать текущий дизайн лендинга «Вектор»

Работай с текущими файлами:

* `index.html`
* `styles.css`
* `script.js`

Не переделывай дизайн с нуля.

Текущая структура, визуальное направление, тёмная палитра, техническая эстетика, документный блок и адаптивная логика уже утверждены.

Нужно выполнить только перечисленные ниже корректировки.

---

# 1. Не менять структуру и тексты

Не изменяй:

* последовательность секций;
* утверждённые русские тексты;
* заголовки;
* кнопки;
* состав блока программы;
* навигацию;
* текущую адаптивную структуру;
* JavaScript мобильного меню, если для указанных ниже изменений это не требуется.

Не добавляй новые смысловые блоки.

Не удаляй существующие секции.

---

# 2. Сократить количество английских технических подписей

Сейчас английские подписи встречаются слишком часто и начинают создавать ощущение цифрового интерфейса.

Необходимо оставить технические подписи только там, где они действительно усиливают композицию.

## Первый экран

Заменить:

```html
SYSTEM / NUTRITION
```

на:

```text
VEC-01 · ПЕРСОНАЛЬНАЯ СИСТЕМА
```

Заменить:

```text
REGULAR MAINTENANCE
```

на:

```text
РЕГУЛЯРНОЕ ОБСЛУЖИВАНИЕ
```

Сохранить:

```text
VEC-01
```

но не дублировать его дважды в одном визуальном узле. Если код уже присутствует в основной подписи, отдельный `VEC-01` удалить.

Итог: на первом экране должно остаться не более двух небольших технических подписей.

## Блок «Исправная система требует регулярного обслуживания»

Удалить подпись:

```text
SERVICE NOTE
```

Оставить только номер секции `01`.

Не заменять её другой английской или русской подписью.

## Блок персональной конфигурации

Заменить:

```text
PERSONAL CONFIGURATION
```

на:

```text
ПЕРСОНАЛЬНАЯ КОНФИГУРАЦИЯ
```

При этом не дублировать одну и ту же фразу дважды.

Сейчас в заголовке блока одновременно используются:

* маленькая техническая подпись;
* крупный заголовок «Персональная конфигурация».

Оставить:

* маленькую подпись `VEC-02 · СПЕЦИФИКАЦИЯ`;
* крупный заголовок `Персональная конфигурация`.

## Визуальная пауза

Заменить:

```text
PRECISION WORK
```

на:

```text
ТОЧНАЯ РАБОТА
```

Сохранить код:

```text
VEC-04
```

## Финальный блок

Удалить:

```text
VEC-06 · COMPLETE
```

Заменить на:

```text
VEC-06 · СИСТЕМА НАСТРОЕНА
```

Подпись должна быть второстепенной и не конкурировать с заголовком.

## Документы программы

Обозначения:

```text
DOC · 01
DOC · 02
DOC · 03
DOC · 04
```

заменить на:

```text
ВЕКТОР · 01
ВЕКТОР · 02
ВЕКТОР · 03
ВЕКТОР · 04
```

Не использовать английское слово `DOC`.

# 3. Переработать блок «Персональная конфигурация»

Сейчас параметры отображаются как линии с точками, расположенными на разном проценте длины:

* привычки;
* график;
* вкусовые предпочтения;
* цель.

Это визуально похоже на шкалы, рейтинги или показатели прогресса.

Такое решение необходимо убрать.

## Новая логика блока

Блок должен выглядеть как лист персональной спецификации, где параметры не измеряются, а фиксируются как учтённые при составлении программы.

Для каждой строки использовать структуру:

* порядковый номер;
* название параметра;
* тонкая техническая линия;
* статус `УЧТЕНО`.

Пример визуальной структуры:

```text
01   Привычки                         УЧТЕНО
02   Рабочий график                   УЧТЕНО
03   Вкусовые предпочтения            УЧТЕНО
04   Цель                             УЧТЕНО
```

## Требования к HTML

Переработать список `.config-sheet__list`.

Не использовать элементы или классы, имитирующие прогресс:

* `.config-sheet__track`;
* вложенный `<i>`;
* позиции через `left: 72%`, `left: 48%` и подобные значения.

Предпочтительная структура строки:

```html
<li class="config-sheet__item">
  <span class="config-sheet__number">01</span>
  <span class="config-sheet__param">Привычки</span>
  <span class="config-sheet__line" aria-hidden="true"></span>
  <span class="config-sheet__status">Учтено</span>
</li>
```

Для остальных строк использовать номера `02`, `03`, `04`.

## Требования к CSS

Удалить:

```css
.config-sheet__track
.config-sheet__track i
.config-sheet__list li:nth-child(...)
```

Создать:

```css
.config-sheet__item
.config-sheet__number
.config-sheet__line
.config-sheet__status
```

Статус `УЧТЕНО` должен:

* быть мелким;
* иметь увеличенный межбуквенный интервал;
* использовать бордовый цвет;
* не выглядеть как кнопка или badge;
* не иметь заливки.

Техническая линия должна быть тонкой и нейтральной.

На мобильной версии строка должна оставаться читаемой и не ломаться хаотично.

При необходимости использовать сетку:

```css
grid-template-columns: auto minmax(0, auto) 1fr auto;
```

На очень узких экранах допускается скрыть техническую линию, но номера, названия и статус должны сохраниться.

# 4. Уменьшить ощущение интерфейса в технической графике

Сохранить:

* тонкую сетку;
* угловые метки;
* номера секций;
* коды `VEC`;
* тонкие технические линии;
* небольшие сервисные отметки.

Но сделать их визуально тише.

## CSS-корректировки

Уменьшить контраст фоновой сетки в `.image-placeholder__grid`.

Текущее значение прозрачности линий снизить примерно на 25–35%.

Уменьшить непрозрачность угловых меток `.image-placeholder::before` и `.image-placeholder::after`.

Они должны быть заметны только при внимательном рассмотрении.

Немного уменьшить межбуквенный интервал у `.technical-label`, чтобы надписи меньше напоминали интерфейс программного обеспечения.

Допустимый ориентир:

```css
letter-spacing: 0.12em;
```

вместо чрезмерно широкого значения.

Не убирать графику полностью.

---

# 5. Уточнить первый экран

Не менять общую двухколоночную композицию.

Нужно сделать первый экран немного более выразительным типографически.

## Заголовок

Увеличить максимальную ширину заголовка с текущих `16ch` примерно до `18–19ch`.

Причина: сейчас переносы могут сделать заголовок слишком узким и дробным.

Не увеличивать размер шрифта резко.

Сохранить спокойный характер.

## Подзаголовок

Увеличить максимальную ширину подзаголовка примерно до `40ch`.

Сделать его цвет немного светлее текущего `var(--text-muted)`, но не белым.

Можно использовать отдельный токен, например:

```css
--text-soft: #afb3b7;
```

Этот токен также можно применять в важных поясняющих текстах, но не заменять им весь второстепенный текст сайта.

## Техническая плашка

`.hero__marks` сделать легче:

* убрать ощущение отдельной тёмной карточки;
* снизить непрозрачность фона;
* оставить тонкую рамку или только две линии;
* уменьшить внутренние отступы.

Плашка должна восприниматься как маркировка рядом с композицией, а не как интерфейсный виджет.

# 6. Уточнить блок «Что вы получите»

Сохранить текущую структуру списка.

Изменить только визуальную деталь:

* вертикальные бордовые отметки `.result-list__rail` сделать немного длиннее;
* снизить их насыщенность;
* выровнять их по центру строки;
* сохранить эффект смещения текста при наведении.

Не превращать отметки в полноценную соединяющую линию между всеми пунктами.

Не добавлять иконки.

---

# 7. Уточнить блок процесса

Сохранить текущую вертикальную последовательность.

Нужно сделать линию между шагами менее похожей на timeline интерфейса.

Изменить `.technical-line--v`:

* уменьшить контраст;
* сделать линию короче;
* не тянуть её на всю доступную высоту;
* убрать слишком заметный градиент.

Линия должна лишь визуально связывать шаги.

Статусы `Шаг 1`, `Шаг 2`, `Шаг 3` оставить на русском языке.

Не добавлять дополнительные коды.

---

# 8. Уточнить блок документов

Сохранить четыре документа и их текущее расположение.

Не менять содержание.

Выполнить следующие корректировки:

## Уменьшить искусственную «разбросанность»

Сейчас используются разные вертикальные отступы:

```css
.document-card--offset-b
.document-card--offset-c
.document-card--offset-d
```

Сделать смещения более деликатными.

Максимальный отступ по вертикали не должен превышать `1rem`.

Ориентир:

```css
.document-card--offset-a { margin-top: 0; }
.document-card--offset-b { margin-top: 0.75rem; }
.document-card--offset-c { margin-top: 0.35rem; }
.document-card--offset-d { margin-top: 1rem; }
```

## Добавить ощущение печатного поля

Внутри каждого документа добавить тонкую вертикальную линию поля слева.

Можно реализовать через `::before` у `.document-card`.

Линия должна:

* располагаться примерно в `0.75rem` от левого края;
* быть очень светлой;
* не пересекать внешний border;
* напоминать поле технического документа.

Не добавлять тени.

## Цвет бумаги

Сделать бумагу немного светлее и нейтральнее.

Не использовать чистый белый.

Сохранить тёплый оттенок, но уменьшить выраженную бежевость.

---

# 9. Уточнить блок «Обо мне»

Сохранить текущую структуру.

Уменьшить декоративность вертикальной линии слева от текста.

Сейчас `.about__copy` использует:

```css
border-left: 1px solid var(--border);
```

Сделать линию короче через псевдоэлемент вместо border на всю высоту.

Линия должна занимать примерно 35–45% высоты текстового блока и располагаться по вертикальному центру.

На мобильной версии эту линию скрыть или заменить короткой горизонтальной.

Не менять текст.

---

# 10. Уточнить кнопки

Сохранить бордовый цвет и текущую форму.

Добавить очень тонкую визуальную деталь:

* небольшую стрелку вправо через CSS или отдельный декоративный `<span aria-hidden="true">`;
* стрелка должна слегка смещаться при наведении;
* не использовать иконки из библиотек;
* не использовать символ `→` непосредственно в тексте ссылки.

Пример структуры:

```html
<a href="#final" class="btn btn-primary">
  <span>Получить персональный план питания</span>
  <span class="btn__arrow" aria-hidden="true"></span>
</a>
```

Применить к двум основным кнопкам:

* на первом экране;
* в финальном блоке.

Стрелка должна быть минималистичной: линия и короткий наконечник.

На мобильной версии кнопки остаются на всю ширину.

---

# 11. Не менять мобильное меню без необходимости

Текущая логика мобильного меню корректна:

* `aria-expanded`;
* закрытие по Escape;
* закрытие после выбора ссылки;
* блокировка прокрутки;
* закрытие при переходе на десктопную ширину.

Не переписывай `script.js`, если изменения кнопок не требуют JavaScript.

Для стрелок кнопок использовать только HTML и CSS.

---

# 12. Проверка адаптивности

После изменений проверить:

* 1440 px;
* 1200 px;
* 960 px;
* 768 px;
* 390 px;
* 320 px.

Особенно проверить:

* блок персональной конфигурации;
* заголовок первого экрана;
* техническую плашку первого экрана;
* документы;
* новые стрелки в кнопках;
* блок «Обо мне».

Не допускать горизонтальной прокрутки.

---

# 13. Что не нужно делать

Не нужно:

* создавать новый дизайн;
* менять цветовую концепцию;
* менять шрифты;
* добавлять библиотеки;
* добавлять новые секции;
* переписывать тексты;
* усиливать автомобильную тематику;
* добавлять новые технические схемы;
* возвращать цифровые шкалы;
* добавлять проценты;
* добавлять HUD-элементы;
* удалять существующую инженерную эстетику;
* переделывать блок программы с нуля.

Верни обновлённые:

* `index.html`;
* `styles.css`.

`script.js` возвращай только в том случае, если он был изменён. В противном случае явно напиши, что JavaScript остался без изменений.

3. какие декоративные элементы стали менее контрастными;
